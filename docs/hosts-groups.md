# Hosts 分组版使用说明

## 使用

1. 安装本地构建的 Github Debug APK，首页点击「Hosts 分组」。
2. 点击「导入 hosts 文件（可多选）」，从系统文件选择器选中一个或多个 UTF-8 hosts 文本文件。ZIP 需要先解压，不能导入 SwitchHosts JSON 备份。
3. 每个文件成为一个分组，名称为文件名，新导入分组默认关闭。之前可读取的单文件配置会迁移为启用的「原有 hosts」。
4. 每组的「展开／收起」按钮显示或隐藏该组 hosts 编辑器，支持多组同时展开；修改后点「保存内容」，或「放弃修改」恢复已保存内容。查看和输入草稿不会启用分组。使用每组开关组合映射；「管理」可重命名或删除组（不删除原文件）。
5. 返回首页开启 VPN 并授权。运行中切换分组或保存已启用分组的新映射，会自动关闭并重新开启一次 VPN；VPN 关闭时只保存配置。重命名和注释等不改变有效映射的操作不会重启。
6. 若两个已启用组将同一域名、同一地址族映射到不同 IP，拒绝本次变更并列出冲突。先关闭旧环境再打开新环境。IPv4 与 IPv6 可以共存。
7. 全部关闭时只转发普通 DNS，不再应用自定义映射。切换后仍需重开业务 App，已建立连接和客户端缓存不能由本工具清除。

## 手动新建

点击「手动新建 hosts 分组」，输入分组名称和 hosts 文本，点「创建」。新分组默认关闭，按需启用。新建和编辑均校验 IP、域名、空内容；已启用组之间的冲突会阻止保存，保留旧配置。

弹窗使用浅色背景和深色文字；编辑草稿保存到应用私有文件，避免将大段文本写入系统 Bundle。

## 数据与边界

- 分组内容保存于应用私有目录的 `hosts-groups.json`，外部源文件删除不会破坏已导入组；修改源文件后需重新导入，不提供后台自动同步。
- 配置使用 AtomicFile 写入；先校验完整启用集合，再保存，再替换不可变 DNS 快照。失败保留原状态。
- 支持注释、多域名同行、大小写归一化、IPv4/IPv6 和原项目的 `.example.com` 通配格式。
- 仅提供地址映射，不添加端口改写或 HTTPS 解密；手机需能访问目标 IP。
- 只有 IPv4 映射时，该匹配域名的 AAAA 返回空结果，避免绕回上游真实 IPv6。未映射域名照常转发。
- 单个导入文件、本次导入总内容和序列化分组配置均限 2 MB；空文件、非法 IP/域名和冲突文件会报错。
- 启用分组管理后，旧单文件入口引导到分组管理，旧网络 hosts 源设置禁用；自定义上游 DNS 设置保留。
- 不兼容 HTTPDNS/DoH 绕过系统 DNS 的请求。开关状态不代表业务请求命中，需用实际响应或后端日志确认。

## 构建与验证

```sh
bash ./gradlew :app:testGithubDebugUnitTest :app:assembleGithubDebug
```

需本地 Android SDK 和 JDK（本次使用 Android Studio JBR 21）。`local.properties` 为机器专用配置，不提交。

验证范围包括 10 项分组单元测试、原项目 1 项示例单元测试、Debug APK 构建和 Android Lint（无错误，仍有警告）。已在 Android 真机验证导入、组合开关、冲突保护、持久化、编辑、新建、删除和运行中 VPN 自动重启。

实际业务 App 的 WebView/Dio 请求、后端命中结果，以及大文本草稿的 Activity 重建恢复尚未验证。VPN 重启不能清除其他 App 的 DNS 缓存和已有连接。

Debug APK 使用开发者本机签名。若已有不同签名版本，不能直接覆盖；安装前请先备份原配置。
